# 회차 PDF: 로컬 사용·검증·자원 예산

이미지 기능 기준 커밋은 `356d86f38435a07ad03fb671aeced44dcf11fc73`이다.
이 문서와 함께 커밋된 개발 브랜치 HEAD가 PDF 배포 후보이며 최종 SHA는
완료 보고/Git 로그로 고정한다. 운영에는 적용하지 않았다.

## 사용

관리자 `/admin/webtoons`에서 작품과 회차를 선택하고 **회차 콘텐츠 방식**을
`이미지 여러 장` 또는 `PDF 한 개`로 선택한다. 표지는 기존 이미지 방식이다.
PDF 선택 → PDF 업로드(진행률) → 관리자 미리보기 → 임시저장 → 회차 공개 순서다.
실패 시 선택 파일을 유지한 채 재시도한다. 작품도 공개해야 독자가 볼 수 있다.
`비공개로 저장`은 공개 취소다. 기존 PDF는 같은 작품 안에서 재사용할 수 있다.
방식을 전환하면 저장 시 이전 방식의 연결을 제거하며 파일 자체를 즉시 지우지 않는다.
참조가 없는 24시간 초과 파일만 기존 관리자 정리 대상이다. PDF 참조도 보존한다.

뷰어는 사이트 내부 세로 스크롤, 페이지/전체, 페이지 이동, 100~300% 버튼 확대와
두 손가락 확대를 제공한다. 가로 이동은 확대 영역 안에서 한다. 이어보기는 이
브라우저의 localStorage에 불변 asset ID·페이지·페이지 내 비율·확대율만 저장한다.
기기/브라우저 간 동기화는 하지 않는다. 처음부터 버튼으로 위치를 초기화한다.
다운로드 버튼은 제공하지 않는다. 열람 시 받은 파일의 저장을 완전히 차단할 수는 없다.

## 관리자 안내와 기술 설명

업로드 화면에는 `PDF 최대 50MB · 최대 200페이지 · 암호화 PDF 미지원`만 안내한다.
worker 예산·렌더링 전략 같은 구현 상세는 아래 개발·운영 검토 문서에 둔다.
화면의 50MB 표기는 간소화한 안내이며 실제 검증 상한은 52,428,800바이트(50MiB)다.
용량·페이지 수·검증 로직은 이번 안내 정리에서 변경하지 않았다.

## 상한과 구현 근거

- 통상 30~40페이지, 허용 1~200페이지. 40페이지 하드 제한은 없다.
- PDF 한 파일 50MiB. MIME/확장자와 실제 헤더/EOF, PDF 파싱, 비암호화 여부,
  페이지 수, 유한한 크기(각 변 최대14400pt, 비율20 이내)를 서버에서 확인한다.
- 페이지 메타데이터와 레이아웃 노드는 최대200개로 제한해 이동/리사이즈/이어보기
  계산 비용을 제한한다. 크롭 영역과 회전을 반영한 고정 슬롯으로 스크롤 높이를 유지한다.
- PDF.js는 현재 페이지 ±2개, 최대5개 캔버스만 유지한다. 페이지당 최대150만 픽셀,
  4바이트 RGBA 기준 최대 약30MB(28.6MiB)의 캔버스 픽셀 버퍼 예산이다.
  멀어진 페이지는 render 취소 → 캔버스0×0 → page.cleanup으로 해제한다.
  문서 이탈 시 loading task/worker를 destroy한다. 전체 페이지 캔버스를 만들지 않는다.
- 파일은 권한 확인 프록시에서 전체 다운로드 후 PDF.js에 제공한다. 네트워크 범위
  요청 방식은 아니다. 50MiB는 모바일 원본 파일 버퍼와 서버의 multipart/검증 복사
  비용을 제한하기 위한 초기 상한이다. Node 프로세스당 PDF 업로드1개, 나머지는429.
- 검증 worker는 old-generation heap192MiB/15초 제한이며 오류·초과 시422와 재시도 안내.
  **192MiB는 전체 서버 RSS 제한이 아니다.** 버퍼·PDF.js worker·이미지 디코딩·GPU는
  별도 메모리다. 큰 스캔 PDF는 페이지 수가 적어도 최적화가 필요할 수 있다.
  운영 승인 전 실제 서버 메모리 여유 및 복잡한 실제 작품/실기기에서 재확인한다.
  50MiB/200은 모든 PDF를 처리한다는 성능 보장이 아닌 자원 방어 상한이다.
- pdfjs-dist **6.5.438**과 같은 패키지의 worker/cmaps/standard_fonts/wasm을
  `/api/webtoons/pdfjs/6.5.438/...`로 제공한다. CDN 의존이나 버전 혼합이 없다.
  서버 파서는 pdf-lib1.17.1. 모두 lockfile 고정이며 Node22.23.0에서 검증한다.

## 재현 테스트

```sh
sh scripts/with-project-node.sh node scripts/webtoons/pdf-check.cjs
sh scripts/with-project-node.sh node scripts/webtoons/pdf-browser-check.cjs
```

기존 로컬 격리 검증을 먼저 통과해야 실행한다. 테스트 파일/계정은 Git 밖 parent
`output/pdf`, `webtoon-admin-account.json`에 있다. 운영 자료·회원정보를 복제하지 않았다.
한글 NanumGothic을 포함한 합성30/40/60페이지로 서버 업로드/메타데이터 순서 확인.
암호화·손상·201페이지·50MiB 초과·일반 사용자 업로드 거부 확인. 익명 비공개 접근,
관리자 미리보기, 직접 Storage/서명 접근 거부, 공개 취소 후 기존URL 차단 확인.
이미지/PDF 혼합 연결도 거부한다. PDF 및 이미지 참조는 GC에서 제외한다.

Chrome390×844 모바일 에뮬레이션: 30/40페이지 한글을 화면 및 텍스트로 확인하고
1→10→20→마지막 순서 이동, 캔버스 최대5개, 확대 버튼/두 손가락 이벤트,
새로고침 이어보기, 처음부터 확인. 관리자503 주입→재시도→미리보기→비공개 저장→공개 통과.
페이지 JavaScript 오류0. 스크린샷은 parent `screenshots-pdf`에서 시각 확인했다.
텍스트 중심 합성 PDF의 검증 worker heap은 약16~18MB, 파싱5~9ms였다.
모바일 캔버스 픽셀 합계 관측 최대1,140,750(약4.6MB), 메인 JS heap 약12~27MB.
측정은 해당 합성 파일/Chrome에서만 유효하다. OS 전체 RSS·GPU·PDF.js worker 합계나
실제 iOS/Android 기기의 안정성 보장은 아니며 고해상도 스캔 작품은 별도 확인이 필요하다.

일반 빌드/회귀 결과와 운영 반영 목록은 WORKLOG 및 webtoons-release.md를 따른다.
